## 功能介绍

GText 是一款基于 LSPosed 框架的 Android 文字替换模块，用于调整应用界面的文案和显示效果。替换发生在本机，**界面上的替换文字不代表服务器记录、商品价格等实际业务数据发生变化**。可替换的范围取决于页面使用的文字渲染方式。

### 核心特性

| 特性 | 说明 |
|------|------|
| 🎯 **字面文本替换** | 按输入原文匹配文本中的相同片段，例如「订单」也会命中「订单详情」 |
| 🔣 **正则表达式** | 批量命中相似文字，如 `\d+分钟前` 一条规则替换所有"N分钟前" |
| 🔡 **忽略大小写** | 英文规则不区分大小写，可与正则叠加 |
| ⚡ **规则热更新** | 接收新配置后，网页 DOM 重新计算；位置限定模式下已保留原文的 TextView 会触发重绘并重算，其他原生入口等待后续赋值/渲染 |
| 🌐 **全局规则** | 一条规则对所有已添加应用生效，无需逐个添加 |
| 🖥️ **系统界面** | 支持替换状态栏、设置等系统界面文字（配合作用域） |
| 👆 **屏幕取词** | 同名控件分别显示，搜索、点选高亮、运行时核验后生成定位条件；仅显示文字需主动选择新建 |
| 📍 **规则生效位置** | Activity、目标进程、控件资源全名、网址、CSS 与字段限定；信息缺失或唯一目标存在歧义时跳过 |
| 🧭 **替换范围** | 按类别控制每个应用参与替换的范围：文字界面 / 菜单弹窗 / 通知媒体 / H5 / 自绘 |
| 🧠 **深度模式** | 额外覆盖资源字符串（Resources.getString）等深层入口，可随时关闭 |
| 🧹 **批量操作** | 一键全部启用 / 全部停用 / 清理停用规则 / 清空规则 |
| 🚫 **一键暂停** | 快捷设置磁贴保存暂停/恢复状态；接收后按通道更新 |
| 🔀 **优先级排序** | 应用规则优先，各组按列表顺序匹配；长按拖拽可调整组内顺序 |
| 🧩 **冲突提示** | 列表和编辑器提示重复或可能重叠的规则，允许继续保存 |
| 🔍 **拼音搜索** | 主页支持全拼/首字母搜索（搜 "jd" 找到"京东"），命中高亮 |
| 🔄 **检查更新** | 读取 GitHub 最新 Release 并展示版本、附件与更新日志；启动时 6 小时自动检查一次 |
| 🔬 **页面自检** | 根据可读节点分析页面特征，辅助判断可尝试的替换通道 |
| 🅰 **字母分组** | 首页按拼音首字母分组，右侧字母条快速定位 |
| 🎨 **替换样式** | 单条规则可设粗体 / 斜体 / 红色 |
| 🕒 **动态变量** | 支持日期、时间、随机数及自定义日期时间格式，在重新匹配时计算 |
| 🔢 **捕获组** | 正则替换支持 `$1`~`$9` 引用分组 |
| 💾 **备份恢复** | 备份应用规则、全局规则及替换相关设置，恢复前完整校验 |
| 🔁 **重启应用** | Root 下重启桌面/系统界面等系统应用，无需重启手机 |
| 🙈 **隐藏桌面图标** | 隐藏后替换功能照常运行；可从 LSPosed 管理器长按模块 →「模块设置」重新打开并恢复 |
| 🚫 **生效范围可控** | 单条规则开关、单应用总开关，全局规则只对已添加应用生效 |

### 应用场景

- 🌐 **本地化翻译**：将应用中的英文替换为中文或其他语言
- ✏️ **文本修正**：修正应用中的错别字或不当表述
- 🎨 **个性化定制**：自定义应用中的文字显示内容
- 🔧 **文案精简**：缩短冗长提示、调整界面用词

### 当前方案不覆盖的情况

| 引擎 | 典型页面 | 原因 |
|------|---------|------|
| Flutter / FlutterBoost | 闲鱼「订单列表/详情」等 | 文本由 Flutter 引擎（Skia）在 C++ 层自绘，Java 层无拦截点 |
| Unicorn 等自绘引擎 | 淘宝「订单详情」 | native Skia 绘制，文本不经过任何 Java API |
| 游戏引擎文字 / 视频硬字幕 | 游戏画面、已经压入视频画面的字幕 | 文字已由引擎或画面像素呈现，没有可替换的 Java 文本入口 |
| WebView 画布模式 | 在线文档等 | Canvas 渲染，DOM 中无文本节点 |

**初步排查**：可用「页面自检」，或通过 `adb shell dumpsys activity top` 查看视图树。若页面主要由 `SurfaceView` / `FlutterView` 构成，可能使用引擎自绘；这只是判断线索，不能据此认定整页所有文字都能或都不能替换。

## 安装与激活

1. **安装模块**
   - 从 [Releases](https://github.com/comewhy/com.comewhy.gtext/releases) 下载最新 APK 安装

2. **激活模块**
   - 打开 LSPosed 管理器 → 模块列表 → 勾选启用 GText

3. **授权 Root（建议但非必需）**
   - 已有可用 LSPosed 服务通道时，GText 无需额外 Root 授权即可同步规则。
   - 授权 Root 可额外启用：文件兜底写入、「重启该应用」、无障碍服务自动恢复。
   - 首次安装或更新后首次打开 GText，未授权 Root 时仍会显示原有 Root 说明弹窗，15 秒倒计时结束后可关闭；同一版本只提示一次。

4. **配置作用域**
   - 在 GText 中添加应用时会**自动弹出 LSPosed 作用域申请**，一键确认即可
   - 也可稍后在 LSPosed 中手动勾选

5. **重新打开目标应用**
   - 首次配置作用域或升级 GText 后，先打开 GText，等待配置发布成功，再重启目标应用一次，加载对应 Hook。首次开启位置限定也需重启。
   - 后续普通规则修改通过热更新同步，已有文字如何更新见[已有页面的更新与暂停恢复](#已有页面的更新与暂停恢复)。

## 使用说明

### 添加替换规则

1. 打开 GText，点右下角 **➕** 选择目标应用
2. 进入应用规则页，点击 **➕** 添加规则
3. 填写 **原文**（应用里显示的文字）和 **替换文**（想改成的内容）
4. 按需开启 **正则表达式** / **忽略大小写** 开关
5. 只想修改某个位置时，在「**生效位置**」选择对应条件，或通过[屏幕取词](#屏幕取词)带入；默认仍为「应用内按文字」
6. 保存后，配置会在后台同步；目标应用接收后，按所在通道更新文字

普通规则采用**字面包含匹配**：原文填写 `订单`，也会替换 `订单详情` 中的 `订单`。若只希望整段等于 `订单` 时替换，可开启正则并填写 `^订单$`。

当前编辑器要求原文和替换文均非空。手动新建时会去除原文首尾空白；通过取词新建或编辑已有规则时保留原文空白。替换文仍会去除首尾空白。输入无效或保存失败时，已填写内容会保留。

普通规则和正则规则都可输入实际页面样本，点击「**试运行文字匹配**」查看当前规则的替换结果、命中数量、耗时和保护原因。试运行只验证文字条件，不核验页面、控件或网址，也不代表实际页面已经替换成功。

1.17 的正则使用本地安全引擎，支持常用分组与 `$1`～`$9` 替换。前后查找断言、反向引用等写法需改写；已有配置仍会保留，但不支持的表达式不会执行。正则最长 512 字符、输入最多 8192 字符、每条最多 256 个命中，并限制重复展开及总工作量；超限跳过该正则，其他规则继续执行。

**替换文支持的语法**

| 语法 | 说明 | 示例 |
|------|------|------|
| `$1`~`$9` | 正则捕获组引用 | 原文 `(\d+)元` → 替换文 `$1元红包` |
| `{date}` | 当前日期 | `2026-10-28` |
| `{time}` | 当前时间 | `20:15` |
| `{datetime}` | 日期 + 时间 | `2026-10-28 20:15` |
| `{random}` | 随机四位数 | `3167` |
| `{date:格式}` | 自定义日期格式 | `{date:yyyy年M月d日}` → `2026年10月28日` |
| `{time:格式}` | 自定义时间格式 | `{time:HH:mm:ss}` → `20:15:03` |
| `{datetime:格式}` | 自定义日期时间格式 | `{datetime:MM/dd HH:mm}` → `10/28 20:15` |

变量在下一次匹配时展开，静止页面不会因为使用 `{time:HH:mm:ss}` 就自动每秒刷新。网页常用格式支持 `yyyy`、`yy`、`M` / `MM`、`d` / `dd`、`H` / `HH`、`h` / `hh`、`m` / `mm`、`s` / `ss`；其他格式及高级正则语法的兼容性可能与原生通道不同。

**替换样式**：规则编辑页可选择「默认 / 粗体 / 斜体 / 红色」，让**替换后的文字**有视觉强调（不改变被替换前的原文）。

> 样式生效范围：只有目标控件以富文本（Spannable）方式渲染时颜色/粗斜体才可见——
> ✅ **支持样式的主要通道**：以 Spannable 渲染的原生控件与通知文字；目标应用可能自行调整样式
> ⚠️ **仅替换文字、样式丢失**：走纯字符串通道的地方，如深度模式的 `Resources.getString`、媒体元数据（歌名/歌手）、菜单 `Menu.add`、最近任务卡片标签
> **仅替换文字，不附加规则样式**：WebView 网页内容、Canvas 自绘文字
>
> 可先在普通页面文字上验证；文字替换成功与粗体、颜色是否呈现，需要分别判断。

**宽松匹配（自动兜底）**：有些页面文字“看起来一样却匹配不上”，可能夹带零宽字符、全角字符或 NBSP 空格。GText 先按原文正常匹配，**只有整段文本没有命中任何规则时**，才尝试去除零宽字符、统一全半角和空格后再匹配，并将命中位置映射回原文。

### 规则优先级与冲突

本版本统一采用以下顺序：**应用规则在前，全局规则在后；每组严格按列表顺序执行**。普通规则、忽略大小写规则与正则规则具有同等优先级。先命中的原文区间归先执行的规则，后续规则只能处理尚未占用的区间；替换出的文字不会再次参与本轮替换。可以长按拖动调整组内顺序。

**先筛选生效位置，再按上述顺序匹配文字。** 范围不符、缺少定位信息或无法确认唯一目标的限定规则会跳过，不占用文字区间。限定更具体的规则不会自动提高优先级；如果希望某个控件使用专属规则，应把它放在同组通用规则前面。

例如应用规则 `订单 → 我的订单` 与全局规则 `订单 → Order` 同时存在时，应用规则生效；若同组前面的 `订单` 先命中，后面的 `订单详情` 不会覆盖这段文字。

列表与编辑器会提示确定重复、字面原文包含关系、以及模式和选项完全相同的正则规则，并排除可以确认生效位置互不相交的情况。不同 CSS 选择器仍可能覆盖同一元素。提示不会阻止保存，也不会自动改变顺序；它不判断任意两段不同正则是否相交，没有提示并不代表所有输入下都不会重叠。

**升级说明：旧版本依赖“普通规则优先”或“全局同原文覆盖”的配置，结果可能改变。请检查冲突提示并按需要排序，随后重启目标应用一次加载新引擎。** 保存失败或输入无效时，编辑器会保留尚未保存的内容。

### 替换范围（每应用通道开关）

应用规则页菜单 →「替换范围」，可分别控制该应用哪些类别参与替换：

| 范围 | 覆盖内容 |
|------|----------|

### 页面自检与诊断

规则页菜单 →「页面自检与诊断」→ 切到目标应用 → 点顶部「自检」：按可见区域分析原生、H5、Compose、Flutter 和自绘内容，分别给出建议。一个引擎控件不会否定周围原生文字的覆盖可能。

报告可复制，并分别展示页面观察、目标主进程实际回报和本机配置试算。目标响应时显示模块版本、成功安装的 Hook 数、加载配置版本与来源、状态、范围及最多三个样本的命中规则/保护原因；无响应时标明未验证。主进程报告不能代表网页或隔离子进程，样本试算也不能证明该页面文字已经过 Hook。

位置限定相关信息包括「范围能力」「构建」「配置格式」和「原生执行模式」。如果报告仍提示旧运行时或旧配置格式，请确认已安装包含 F1 的版本、配置发布成功并重启目标应用。诊断中的纯文字样本缺少真实定位信息，会跳过限定规则；核验具体位置请使用取词高亮。

### 已有页面的更新与暂停恢复

本版本会为已处理的网页 DOM 保留原文。网页接收新配置后，已有文字、标题和受支持属性会从原文重新计算；暂停、停用或清空规则时恢复仍由 GText 管理的值。网页自己更新文字时，以网页的新值为准，避免恢复过期内容。

覆盖普通 DOM 文本、页面标题、`placeholder`、`alt`、`title`、`aria-label`、按钮显示值、同源 iframe 和开放 Shadow DOM；页面新增文字或相关属性发生变化时继续处理。下拉选项的可见文字可以替换，`option.value` 提交值保持原样。

普通输入框的用户值、可编辑正文、`textarea` 正文、`code`、跨源 iframe、封闭 Shadow DOM 和网页 Canvas 不在处理范围内；可编辑控件的 `placeholder`、`title` 等支持的提示属性仍可处理。匹配以单个文本节点为单位，暂不支持把跨多个标签的文字拼成整句匹配。Java 与 JavaScript 的高级正则和日期格式可能存在差异。

**开启位置限定并重启目标应用后**，GText 会分别保留受支持 TextView 的 `text` / `hint` 原文。接收配置变化后会触发窗口重绘，在后续 TextView 绘制时重算；控件 ID、绑定或页面变化也会重新判断范围。暂停、停用、清空规则或退出限定范围时，从受管理原文重算；没有其他适用规则时恢复原文。目标应用重新设置文字时，以新输入为准。

未进入位置限定模式的普通原生通道，以及菜单、通知、Canvas、自绘和资源字符串，仍需后续赋值/渲染等事件才能更新，不承诺立即恢复历史显示。开启位置限定前已经产生、又没有可靠原文记录的替换结果也不能自动反推恢复。安装时关闭的通道在重新开启后仍需重启目标应用安装对应 Hook。

### 屏幕取词

在目标应用中直接点选文字创建规则，免去手动输入：

1. 规则页菜单 →「屏幕取词」→ 首次使用按提示开启无障碍服务「**GText屏幕取词**」
2. 再次点击「屏幕取词」，应用自动退到后台
3. 切换到目标应用，点击屏幕顶部的「**取词**」按钮
4. 搜索或点选列表里的具体候选，核对屏幕红框；高亮覆盖层会拦截触摸，避免误触目标按钮
5. 目标主进程核验当前字段、原文和稳定定位，确认时再次核验。核验到唯一命中规则时优先打开对应的应用规则或全局规则编辑，否则将原文和定位条件带回新建编辑器
6. 只有显示文字或找不到可靠定位时，可重新采集，或主动选择「用显示文字新建」并手动填写原文与范围

目标应用尚未添加规则时也可取词。候选会保留同名控件的不同位置并分批显示；滚动、文字变化或切换窗口后，旧候选可能失效，需要重新采集。取词仅自动核验目标主进程，主进程结果不能代替子进程定位。

> 只能读取系统无障碍接口可见的文字，部分自绘界面可能读不到。

**取词服务自动恢复**：Android / MIUI 在应用被强行停止（划掉最近任务）后会自动关闭其无障碍服务（系统行为）。授予 GText **Root** 后，打开 GText 或使用取词时会通过 Root 自动重新启用该服务，无需再手动去无障碍设置授权。未授权 Root 时可将其锁定在最近任务、省电策略设为「无限制」以减少被关闭。

### 限定规则生效位置

编辑规则 →「**生效位置**」，选择模式；点「**编辑高级定位条件**」可检查或手动填写条件。规则页菜单中的「替换范围」控制整类通道是否开启，这里的「生效位置」控制单条规则在什么位置参与匹配；对应通道也需要开启。

| 模式 | 条件与实际作用 |
|------|----------------|
| 应用内按文字 | 不附加位置条件，在应用已开启且受支持的通道中按文字匹配 |
| Activity 容器内 | 填写 Activity 完整类名，选择 `text` 或 `hint`；只限定受支持的原生文本控件字段 |
| 指定原生控件 | 填写 `package:id/name` 资源全名及字段，可叠加 Activity；单个控件必须填写目标进程名 |
| 指定网址 | 填写 HTTP/HTTPS 完整网址及字段，可选择包含子路径或同时匹配 `#` 后的片段 |
| 指定网页元素 | 在网址条件上增加稳定 CSS 选择器及字段；单个元素必须填写目标进程名 |

例如，同一应用里有多个「确定」，可先取词选中目标按钮，核对红框与原文，再在编辑器填写替换文。自动定位成功后会带入 Activity、控件资源名与进程，或网址、网页元素与进程；保存前仍可检查条件。

单个控件或元素会在运行时核验唯一性。原生核验统计该进程窗口内符合条件的同 ID 控件，隐藏控件也参与计数；重复 ID 或核验不完整时跳过。只有明确勾选「匹配所有符合条件的同类控件 / 元素」才允许多个目标。Activity 可能包含多个页签，不能单凭 Activity 限定某个 Fragment，也不会因此覆盖容器里的网页、菜单、通知或自绘文字。

网址始终忽略查询参数。手动新建默认忽略 `#` 后的片段；hash 路由需勾选片段，网页取词生成的条件会自动包含当前片段。勾选「包含子路径」后，`https://example.com/order` 可匹配 `/order/123`，不会匹配 `/orders`；单凭网址也不能区分查询参数不同的订单。

网页字段可选 `text`、`placeholder`、`alt`、`title`、`aria-label`、`value`、`pseudo`；每条规则只处理所选字段，`value` 仅用于受支持按钮的显示值。手动 CSS 选中容器且字段为 `text` 时，会包含其后代的可处理文字；提示属性等其他字段只检查选中元素自身。选择器应使用稳定标识，不能依赖将被替换的文字属性（如 `[title="确定"]`）、GText 管理属性或 `:scope`。

网页自动定位要求文字直接所属元素自身有稳定 ID 或测试标识，文本目标还需只有一个可处理文字字段。如果只有父容器有标识，或元素内有多段文字，会提示手动限定区域，不会把相邻文字自动纳入点选目标。

原生首版支持 TextView/Button 的 `text` 和 `hint`；网页支持单个已登记系统 WebView 的元素文字及受支持属性，开放 Shadow DOM 与同源 iframe。多个 WebView、网页子进程目标、第三方内核或合成无障碍文字不能可靠确认时会说明原因。页面锚点、列表指定条目以及 Compose/Canvas/Flutter 定位尚未接入。

**首次开启位置限定时，请等待发布成功，再重启目标应用。** 此后配置、控件 ID、绑定或页面变化会按受管理原文重算；为保留原生及 HTML 的输入原文，Resources/String 等前置入口会延后，部分仅依赖这些入口的深层覆盖可能减少。文字样本试运行只检查文字与正则；真实定位需通过取词高亮核验。

### 替换系统界面文字

1. 在 LSPosed 中将「系统界面（SystemUI）」「设置」等勾选进 GText 作用域
2. 在 GText 中添加对应应用（如"系统界面"，包名 `com.android.systemui`）并添加规则
3. 使用规则页菜单的「**重启该应用**」（需 Root）。GText 会先等待配置发布，再尝试重启；系统界面可能短暂黑屏闪烁

### 快捷磁贴（一键暂停）

下拉通知栏 → 编辑磁贴 → 添加「**GText 替换开关**」：

- 点击保存暂停/恢复设置；目标应用接收配置后，网页 DOM 恢复/重新计算，位置限定模式下受管理的 TextView 会触发重绘并重算，其他通道等待后续赋值/渲染事件
- 适合临时给别人看手机、截图等场景

### 备份 / 恢复

设置页 →「备份配置」导出应用规则、全局规则、各应用启停与通道设置，以及暂停替换、激活提示、深度模式三个替换设置。桌面图标隐藏状态、自动检查更新设置和系统无障碍授权不包含在备份中。

1.17 的新版备份会保存每条规则的生效位置，使用支持 F1 备份格式（schema 2）的 GText 版本恢复。旧版备份仍可导入，未包含位置条件的规则保持原来的按文字匹配方式。

「恢复配置」先完整检查文件，再保存替换配置。任何应用或规则存在结构、正则语法或位置条件错误（包括未知范围类型/字段）时，整次恢复失败，原数据保持不变。语法有效但安全正则引擎不支持的旧表达式可保留，需改写后才会执行。文件中缺失的应用规则段、全局规则段或替换设置项保留本地值；明确提供空数组则清空对应规则段。提供的规则段整体替换，不执行规则合并。

旧备份缺失或重复的规则标识会在导入时规范化，保留规则内容与顺序。如果本机配置已损坏而无法读取，恢复时需要同时包含应用规则、全局规则和完整替换设置的备份，避免用默认值补齐未知数据。

### 排查"为什么没替换"

1. **检查替换范围**：规则页菜单 →「替换范围」，确认该类文字所在的通道（菜单 / 通知 / H5 / 自绘）没有被关闭
2. **检查生效位置**：确认 Activity、进程、资源名、网址和字段正确；遇到目标不唯一或信息不足时重新取词。首次开启限定须等待配置发布成功并重启目标应用
3. **核对诊断**：在「页面自检与诊断」查看目标加载的版本、配置和范围能力；文字试运行成功只表示文字条件正确
4. **检查正则与优先级**：查看无效表达式、保护原因和冲突提示；同组靠前的通用规则可能先占用文字区间
5. **按通道尝试深度模式**：依赖资源字符串入口的普通规则可开启深度模式后重启再试；位置限定模式会延后前置文本处理，单纯打开深度模式不能补齐缺失的定位信息

## 常见问题

| 问题 | 解决方案 |
|------|----------|
| 规则不生效 | 检查 LSPosed 作用域是否勾选；规则是否启用；等几秒让热更新生效，或重启目标应用 |

## 数据同步机制

规则、全局规则、应用开关、替换范围和设置作为一个带版本的完整配置保存。保存成功后，LSPosed 官方服务通道与文件兜底通道各自后台发布，避免把新规则与旧开关拼在一起。

F1 使用完整 schema 2 配置，旧格式兼容副本仅包含无范围规则，防止旧模块忽略限定条件后扩大替换范围。新版同版本优先完整格式，接受后不降回兼容副本；更新完整副本暂时失败时保留最近完整配置。旧模块仍可能持有更新前的输出，升级与首次限定都须发布成功后重启目标应用。

首页仍显示原有的通道、取词和 Root 三个信号灯。**通道灯只表示 LSPosed 服务是否连接，不代表每个目标应用都已加载当前配置。** 服务未连接时仍可能通过文件兜底同步。目标进程是否运行、是否已升级 Hook、作用域是否正确，都会影响接收。首次升级本版本后应重启目标应用一次。

LSPosed 服务通道不要求额外授予 GText Root；文件兜底与「重启该应用」需要 Root，文件兜底还需设备支持相应的文件锁能力。规则页的重启操作会等待当前配置发布，最多 5 秒；未发布时不会继续重启，并提供重试入口。同步失败时，本机已保存的规则仍然保留。

远程与 Root 使用独立任务队列，尚未执行的旧版本会合并到最新配置。相同版本成功发布后按通道去重，失败可重试；服务重连会重新验证远程目的地。最新版本任一通道成功即可通过重启前检查，其他通道继续后台处理；目标加载情况可在页面诊断中按需查看。

## 性能说明

- 规则按已确认的列表优先级匹配，每个配置版本维护独立缓存
- 远程通道监听配置变化，并每 3 秒检查可读配置作为兜底；只有新版本才切换匹配器和网页规则
- Hook 按「替换范围」选择性安装：关闭 H5 / 自绘等类别时，对应 Hook 完全不安装，进一步降低开销
- 深度模式默认开启；如需极致轻量或遇到兼容问题，可在设置页关闭
- 全局规则只对已添加应用生效，未添加的应用在匹配入口快速返回
- 单条替换结果超过 500 字会自动截断，避免超长文本破坏页面布局
- 替换文含 `{date}`、`{time}`、`{datetime}`、`{random}` 或自定义格式变量时不缓存展开后的结果；重新计算时使用当时的值
